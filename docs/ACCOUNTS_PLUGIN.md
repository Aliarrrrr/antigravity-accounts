# Antigravity Accounts · 0.4.0-preview.18

本版同时提供独立 Accounts 包与中文成套兼容包。成套包的自动准备、退出后应用、组件状态和恢复限制见[兼容更新说明](COMPATIBILITY_UPDATES.md)。独立包的安装顺序保持如下约定。

Windows x64 账号插件：将独立授权的 Google 账号分组放入 Antigravity 原生模型列表，保留官方模型选项、主题和 View Usage。各账号分别使用自己的额度；插件不合并或转移额度。模型请求仍由原生语言服务直接发往 Google。

preview.16 包含 preview.15 的 Antigravity 2.32.1 兼容修复，并修正宿主采用 BaseWindow/WebContentsView 时的账号切换窗口访问。preview.15 仅作为本地修复，未单独发布。保留 2.31.2、2.31.0、2.29.0 和 2.28.2 的已有支持，以及 preview.14 的未知更新原生登录确认入口。需要完整分发包与本机宿主适配。仅安装 `plugin.json` 不会启用切换。未知版本不写入账号补丁，当前未在 Marketplace 上架。运行检查范围见包根目录 `VALIDATION.md`；先前只显示账号菜单和管理面板的检查不能证明切换成功。SSH 远程会话不在独立账号切换支持范围内。

## 安装

1. 解压完整 ZIP，保留其中目录结构。
2. 正常退出 Antigravity。启用“常驻系统托盘”时，请从托盘选择“退出”；仅关闭窗口不会退出进程。
3. 宿主仍是原来的版本且装有 Accounts 时，运行新解压包中的 `Restore.cmd`；若同时有中文适配，先恢复中文层。宿主已被官方更新替换为已支持的新原程序时，直接执行下一步，安装器会保存旧安装记录并为新版本重新准备适配，避免把旧宿主恢复到新安装目录。账号授权会保留。
4. 运行新版 `Install-Preview.cmd`。安装器检查当前程序，保留原始 `app.asar` 和 `language_server.exe` 后写入适配。桌面、语言服务、更新器或无法识别的相关进程仍在运行时，安装会停止。
5. 如需中文界面，重新应用中文层。运行 `Start-With-Accounts.cmd`，启动并打开原生模型菜单。

无需另装 .NET、Node、Python 或 PowerShell 7。安装辅助脚本使用本机官方 Electron 的 Node 模式。自定义安装位置时，将 `ANTIGRAVITY_INSTALL_ROOT` 设置为包含 `Antigravity.exe` 的目录。`Prepare.cmd` 只生成本机程序副本，不应用到安装目录。

## 添加和切换账号

2026 年 11 月 14 日，preview.16 已在本机 Antigravity 2.32.1 的 BaseWindow/WebContentsView 界面完成两个已保存账号 A → B → A 切换，确认过程结束，项目和模型保留，并切回原主账号。本轮未发送模型请求，也未验证实际扣额或跨账号生成。

在原生模型菜单中打开“账号设置…”，输入可选标签并点击“添加账号”，亲自在 Google 网页完成授权。在同一面板设定唯一主账号，其余账号作为附属账号。添加、删除、标签编辑、重新授权、主账号配置和数据使用设置都位于该面板；模型列表保留切换和管理入口。未配置独立账号时，应用继续使用原官方登录。

preview.11 将模型菜单账号名称与状态分栏，使用独立勾选、等待、展开和设置图标。管理面板统一控件与窄屏布局，显示当前/主账号等状态标签，减少邮箱和按钮边框的重复显示。

授权等待期间可在同一面板点击“取消授权”，取消本次登录尝试，已保存账号保持不变。账号列表最多保存 100 个账号；达到上限后仍可重新授权已有账号。

首次启用独立主账号和所选账号后，需要完全退出并重新启动 Antigravity。之后点击其他账号分组即可请求切换，无需重启 App 或语言服务。切换会暂停新的提交，等待原生任务结束，再确认目标身份、项目、模型和额度元数据。取消等待只取消切换，不取消原有任务。

切换前会保存原模型。新账号仍可用时保留该模型；不可用时，须在原生列表明确选择可用模型后才能发送。确认失败或任务状态无法读取时，新的发送保持暂停。查明原因后可在目标分组选择“重新确认此账号”。托盘“额度账号…”打开同一模型菜单。

在管理面板中可修改标签、重新授权及设置数据使用授权。默认对账号切换后出现的数据使用弹窗关闭收集选项，待原生保存成功后确认；可改为勾选并确认，或每次手动处理。2.31.0 的弹窗标题为 One last thing before getting started…，按钮为 Continue。首次使用、条款类型变化、无法识别及读取或保存失败时保留原生弹窗。preview.10 修复了设置已保存却因读取 React 旧状态而未确认的问题。出现 `Verify your account to continue.` 时，请在 Google 官方流程处理账号验证，再重新确认；重新授权不能替代这项验证。参见 [Google 账号验证说明](https://support.google.com/accounts/answer/15437069)。

## 删除账号

在“账号设置”中点击附属账号的“删除账号”，核对确认行中的邮箱，再点击“确认删除”。这会移除本机插件保存的授权，再次使用需重新添加；不删除 Google 账号。正在使用的账号须先切换到其他账号，主账号不能在运行中删除。授权或切换尚未结束时，删除入口不可用。删除其他附属账号不改变当前选择及其余账号。

## 授权与本机数据

- 账号通过 `accounts.google.com` 授权，`oauth2.googleapis.com` 交换或续期，`openidconnect.googleapis.com/v1/userinfo` 查询独立账号身份。模型及项目/额度元数据由原生服务向 Google 请求。
- OAuth 桌面客户端配置取自匹配的本机语言服务公开常量，不读取官方保存的登录。当前授权范围为 `openid`，以及 `https://www.googleapis.com/auth/` 下的 `cloud-platform`、`userinfo.email`、`userinfo.profile`、`cclog`、`experimentsandconfigs`。实际许可由 Google 决定。
- 账号默认存于 `%LOCALAPPDATA%/AntigravityAccounts`，使用 Windows DPAPI CurrentUser 加密。安装器登记实际目录，组件、启用标记和修复均使用该位置，避免不同启动环境读取空目录。
- 组件和宿主通过子进程 stdio 通信；界面只接收账号摘要和状态，不接收 token。独立账号凭据交给原生语言服务使用，原官方账号的 Authorization 不经过插件。
- 不导入 Cookie、原生认证数据库或 Windows 凭据管理器数据，不复制项目和会话。启用独立路径后，组件故障不会悄悄退回原官方身份。

本项目不代表 Google。采用本机官方桌面客户端公开 OAuth 配置的第三方分发方式仍待 Google 确认；相关申请不等于批准。

## 更新与恢复

使用 `Start-With-Accounts.cmd` 可在启动前检查并修复已支持的更新。安装会把独立修复文件缓存到账号状态目录的 `recovery-package-*`，因此原解压目录移除后仍可修复。版本号变化而相关完整脚本、RPC 依赖和原生程序仍兼容时可以继续使用。未知接口或原生程序变化会停止写入补丁；当前官方程序完整且没有账号接入代码时，可在启动前选择使用原生登录继续。该身份可能与之前的额度账号不同，原账号授权仍保留，后续兼容包可以恢复账号功能。取消确认则保持关闭。部分替换、文件损坏、记录冲突、未知写入错误和仍在运行的安装器继续阻止启动。

官方更新的账号恢复接管准备失败时，仍继续安装，但不自动重开程序。安装完成后从原有中文快捷方式启动，再确认是否使用原生登录，避免直接重开绕过身份提示。

应用内“重启安装更新”会先准备外部等待进程，待旧 App、安装器退出且文件停止变化后，调用登记的修复与启动入口。真实 NSIS 升级尚未验证。直接双击更新后的官方 EXE 会绕过启动前检查。

恢复时正常退出 Antigravity，再运行 `Restore.cmd`。安装收据为账号状态目录中的 `adapter-installation.json`，原程序及恢复清单位于同目录的 `restore-*`。恢复会移除插件运行文件并保留主动添加的账号资料。当前程序与收据不匹配时会拒绝覆盖；不要删除恢复文件后尝试用旧程序覆盖新版本。

若叠加外部中文适配，手动升级或恢复 Accounts 前须先恢复中文层，完成 Accounts 操作后再应用中文层。中文保护入口需要使用支持 preview.14 原生登录确认流程的新版启动器，旧版中文启动器可能继续阻止未知更新启动。当前本机已更新并检查该启动器。外部中文工具不在本包中，也未通过本仓库单独发布。

preview.11 修复了 Windows 路径大小写导致已识别 `agy-node.cmd` 后台启动器被误判的问题。匹配仍要求固定命令、参数和父子进程关系；真实 App、更新器或无法识别的进程仍会阻止安装和恢复。新版 `Restore.cmd` 使用已有 `schemaVersion: 1` 安装记录及其备份清单，不会用新包文件代替备份原程序；当前程序已更新或修改而不匹配时仍拒绝覆盖。
